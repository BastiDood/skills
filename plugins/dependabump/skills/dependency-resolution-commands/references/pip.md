# `pip`

Commands for projects that install with `pip` from `requirements*.txt`, including `pip-tools` projects that compile `requirements*.in` into pinned `requirements*.txt` files.

## Detect

A `pip` project has `requirements*.txt` files and no other lockfile; a `pip-tools` project also has matching `requirements*.in` sources. Each compiled `.txt` starts with `This file is autogenerated by pip-compile`. Treat each requirements file, or each `.in` with its `.txt`, as one member.

```bash
# List requirements and constraints files.
# Mutates: nothing.
rg --files --glob "requirements*" --glob "constraints*"
```

## Outdated

`pip list` reads the installed environment; `--not-required` limits it to packages that no other installed package requires, which approximates the direct dependencies. Install the requirements first ("Update").

```bash
# List outdated top-level packages in the environment.
# Mutates: nothing.
pip list --outdated --not-required
```

In a `pip-tools` project, the dry run prints the compiled file that a full upgrade would write; compare its pins with `$TXT`.

```bash
# Print the pins that a full upgrade within the .in ranges would write.
# Mutates: nothing.
pip-compile --dry-run --upgrade --output-file "$TXT" "$IN"
```

## Inspect

`pip` has no command that reports publish dates; the PyPI JSON API supplies them.

```bash
# Print every published version with its upload time and yank state.
# Mutates: nothing.
curl --silent --location "https://pypi.org/pypi/$PACKAGE/json" | jq '.releases | map_values({uploaded: .[0].upload_time_iso_8601, yanked: .[0].yanked})'
```

```bash
# Print the dependency ranges, Python requirement, and yank state of one version.
# Mutates: nothing.
curl --silent --location "https://pypi.org/pypi/$PACKAGE/$VERSION/json" | jq '.info | {version, requires_python, requires_dist, yanked, yanked_reason}'
```

`requires_dist` entries with an `extra == "..."` marker are optional extras.

## Dependents

`pipdeptree` reads the installed environment and prints each dependent with its declared range as `[requires: NAME>=X]`; it is a separate tool installed into the environment.

```bash
# Show the installed packages that depend on a package, with their declared ranges.
# Mutates: nothing.
pipdeptree --reverse --packages "$PACKAGE"
```

In a `pip-tools` project, the `# via` lines under each pin in the compiled file name its dependents without installing anything.

## Duplicates

One environment holds one version per package. `pip-compile` writes one pin per package; duplicates exist only across requirements files that pin the same package to different versions.

```bash
# Print every pin of every compiled or plain requirements file.
# Mutates: nothing.
rg --line-number --fixed-strings "==" --glob "requirements*.txt"
```

`pip` has no dedupe command. In a `pip-tools` project, use the targeted "Update" for each pair that pins the package. In a plain `pip` project, rewrite each pin as in "Constrain".

## Constrain

Rewrite the specifier with the file-edit tool: raise only the floor to `$VERSION` and keep the operator and any explicit upper bound (`>=1.2,<1.5` becomes `>=$VERSION,<1.5`). In a `pip-tools` `.in` file, an exact `==` pin becomes `>=$VERSION,<$NEXT_MAJOR`, where `$NEXT_MAJOR` increments the first non-zero component of `$VERSION` (`1.3.4` gives `2`, `0.4.2` gives `0.5`); in a plain `pip` requirements file, an exact pin stays exact at `==$VERSION`.

## Update

```bash
# Update all pins within the requirements of one `.in`/`.txt` pair.
# Mutates: the compiled requirements file.
pip-compile --upgrade --output-file "$TXT" "$IN"
```

In a `pip-tools` project, the `==$VERSION` constraint applies to this one compile; the `.in` file keeps its range and every other pin stays unless it conflicts. Compile each `.in`/`.txt` pair that pins the package.

```bash
# Land a package on exactly the target version in one compiled file.
# Mutates: the compiled requirements file.
pip-compile --upgrade-package "$PACKAGE==$VERSION" --output-file "$TXT" "$IN"
```

`pip-sync` installs exactly the pins of the listed files and uninstalls every other package.

```bash
# Make the environment match the compiled files.
# Mutates: the environment.
pip-sync requirements.txt requirements-dev.txt
```

In a plain `pip` project, the pin that "Constrain" writes is the update; repeat `--requirement` for each file.

```bash
# Install the pinned versions into the environment.
# Mutates: the environment.
pip install --requirement requirements.txt
```

## Add

`pip` and `pip-tools` have no add command. Append the line `$PACKAGE$RANGE` with the file-edit tool to the `.in` file (`pip-tools`) or the `requirements*.txt` file (plain `pip`) of the right group, then run `pip-compile --output-file "$TXT" "$IN"` in a `pip-tools` project.

## Remove

`pip` and `pip-tools` have no remove command. Delete the requirement line and its `--hash` continuation lines with the file-edit tool, then run `pip-compile --output-file "$TXT" "$IN"` and "Update" in a `pip-tools` project.

```bash
# Uninstall a package from the environment in a plain pip project.
# Mutates: the environment.
pip uninstall --yes "$PACKAGE"
```

## Override

`pip` has no override mechanism; constraints live in a constraints file passed as `--constraint FILE` or as a `-c FILE` line inside a requirements file. Constraints only narrow versions.

To test whether a constraint entry is redundant in a `pip-tools` project:

1. Run `pip-compile --upgrade-package "$PACKAGE" --output-file "$TXT" "$IN"` and record the pins that the "Duplicates" listing prints.
2. Delete the entry from the constraints file with the file-edit tool.
3. Run the same `pip-compile` command and print the "Duplicates" listing again.
4. If the pins changed, restore the entry and recompile; otherwise leave it deleted.

Without `--upgrade-package`, `pip-compile` keeps the existing pin and hides the effect of the deletion.

## Patch

`pip` has no patch flow; a patched package is a direct URL requirement (`$PACKAGE @ git+https://...`) or an `-e` line in a requirements file.

```bash
# List direct URL requirements.
# Mutates: nothing.
rg --line-number --fixed-strings " @ " --glob "requirements*"
```

To remove a patch, replace the URL line with a registry requirement `$PACKAGE$RANGE` using the file-edit tool, then recompile the pair in a `pip-tools` project.

## Unused

Find unused dependencies by static analysis. A distribution's import name can differ from its package name (`PyYAML` imports as `yaml`). Read the installed package under the environment's `site-packages` (its `top_level.txt` or package directory) for the import name, then search the project for it. A package that appears only in manifests and the lockfile is a candidate; a package that appears only in tests or tooling is misplaced.

```bash
# List the project files that mention an import name, outside ignored directories such as .venv.
# Mutates: nothing.
rg --files-with-matches --fixed-strings "$IMPORT_NAME"
```

Before removing a candidate, read its source for entry points, plugins, or console scripts that a configuration file or script loads without an import.

## Deprecated

`pip` warns about a yanked pin while resolving it. The dry run resolves without installing.

```bash
# Resolve the pins and print a warning for each yanked version.
# Mutates: nothing.
pip install --dry-run --requirement requirements.txt
```

PyPI reports a deprecated, archived, or quarantined project in the `project-status` field of its Simple API.

```bash
# Print the project status of a package.
# Mutates: nothing.
curl --silent --location --header "Accept: application/vnd.pypi.simple.v1+json" "https://pypi.org/simple/$PACKAGE/" | jq '."project-status"'
```

## Hygiene

`pip` and `pip-tools` prune none of these entries:

- Constraints file entries: stale when no compiled file pins the package or the entry no longer changes the pins.
- `--index-url`, `--extra-index-url`, `--find-links`, `--no-binary`, `--only-binary` lines and the same keys in `pip.conf` or `PIP_*` variables: stale when no remaining package needs them.
- `--hash` lines in hand-maintained files: stale after any version change.
- Options in the `pip-compile` header command (`--extra`, `--unsafe-package`): stale when they name extras or packages that no longer exist.
- Compiled `.txt` files: stale when their `.in` source is gone.
