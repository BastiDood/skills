# Introduced Lists and Preserved Depth

<original_verbatim_text>

The harness injects other information like:

- The system prompt
- The MCP descriptions
  - Tool definitions
- The user messages

All you need to know is that context adds up.

</original_verbatim_text>

<expected_on_slide_content>

- System prompt
- MCP descriptions
  - Tool definitions
- User messages

</expected_on_slide_content>

<expected_presenter_notes>

- The harness injects other information like:
  - The system prompt
  - The MCP descriptions
    - Tool definitions
  - The user messages
- All you need to know is that context adds up.

</expected_presenter_notes>

<anti_example>

- The harness injects other information like:
  - The system prompt
  - The MCP descriptions
  - Tool definitions
  - The user messages
- All you need to know is that context adds up.

</anti_example>

<why_the_anti_example_fails>

It copies setup and conclusion sentences that the presenter can say, while flattening `Tool definitions` out of its source-authored parent. The good slide keeps only the list the audience must scan and preserves its meaningful depth.

</why_the_anti_example_fails>

<rule_demonstrated>

Indent an introduced list once and preserve its nested depth in presenter notes. On the slide, remove the spoken setup sentence when a title can frame the compact list.

</rule_demonstrated>
