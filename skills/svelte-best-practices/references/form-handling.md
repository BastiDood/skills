# Form Handling in Svelte

## Core Principle

**`use:enhance` + SvelteKit form actions as default.** Server-side validation with Valibot, progressive enhancement, submitter disabling. **Fallback to `onsubmit` + TanStack Query only in SPA mode** (no `+page.server.js`).

## Stack

### Tier 1 (Default) — `use:enhance` + Form Actions

- `enhance` from `$app/forms` — Progressive enhancement
- `fail` from `@sveltejs/kit` — Constraint error responses
- `decode-formdata` — Decodes `FormData` into typed objects (server-side)
- `valibot` — Schema validation (server-side)

### Tier 2 (SPA Fallback) — `onsubmit` + TanStack Query

- `decode-formdata` — Decodes `FormData` into typed objects (client-side)
- `valibot` — Schema validation (client-side)
- TanStack Svelte Query `createMutation` — Mutation management

## Tier 1: `use:enhance` + Form Actions (Default)

### Core Pattern

#### `+page.server.ts`

```typescript
import { fail } from '@sveltejs/kit';
import * as v from 'valibot';
import { decode } from 'decode-formdata';
import type { Actions } from './$types';

const CreateItemSchema = v.object({
	name: v.pipe(v.string(), v.minLength(1)),
	amount: v.number(),
});

export const actions = {
	default: async ({ request }) => {
		const formData = await request.formData();
		const data = v.parse(CreateItemSchema, decode(formData, { numbers: ['amount'] }));

		const existing = await db.getItemByName(data.name);
		if (existing)
			return fail(409, {
				message: 'An item with this name already exists',
				data: { name: data.name },
			});

		await db.createItem(data);
	},
} satisfies Actions;
```

`v.parse` for schema validation — a schema violation means the frontend sent unexpected data (programmer error). `fail()` for **constraint violations** (duplicates, business rules) — these are user-facing input failures.

#### `+page.svelte`

```svelte
<script lang="ts">
	import { enhance } from '$app/forms';
	import { assert } from '$lib/assert';

	// Types are generated by SvelteKit.
	let { form } = $props();
</script>

<form
	method="POST"
	use:enhance={({ submitter }) => {
		assert(submitter instanceof HTMLButtonElement, 'submitter must be a button');
		submitter.disabled = true;

		return async ({ update }) => {
			submitter.disabled = false;
			await update();
		};
	}}
>
	{#if form?.message}
		<p class="error">{form.message}</p>
	{/if}
	<input name="name" type="text" value={form?.data?.name ?? ''} required />
	<input name="amount" type="number" required />
	<button type="submit">Create</button>
</form>
```

### Named Actions + Multiple Submit Buttons

Each button is the `submitter` — disabled individually. No shared `$state` needed.

```svelte
<form
	method="POST"
	action="/members/?/promote"
	use:enhance={({ submitter }) => {
		assert(submitter instanceof HTMLButtonElement, 'submitter must be a button');
		submitter.disabled = true;
		return async ({ update }) => {
			submitter.disabled = false;
			await update();
		};
	}}
>
	<button type="submit">Promote</button>
	<button type="submit" formaction="/members?/remove">Remove</button>
</form>
```

Always use **absolute paths** for `action` and `formaction` (e.g., `/members?/promote`, not `?/promote`). Pinning to absolute paths prevents breakage when files are moved.

### Controlling `update()` Behavior

```typescript
return async ({ update }) => {
	submitter.disabled = false;
	await update({ reset: false }); // keep form values (useful for edit forms)
};
```

Options: `{ reset?: boolean, invalidateAll?: boolean }`. Default: both `true`.

### Dialog / Sheet Integration

Close the dialog in the returned callback, then call `update()`. See [Conditional State](conditional-state.md) for the shell/form split pattern.

```svelte
<script lang="ts">
	import { enhance } from '$app/forms';
	import { assert } from '$lib/assert';

	interface Props {
		onSuccess: () => void;
	}

	let { onSuccess }: Props = $props();
</script>

<form
	method="POST"
	use:enhance={({ submitter }) => {
		assert(submitter instanceof HTMLButtonElement, 'submitter must be a button');
		submitter.disabled = true;

		return async ({ result, update }) => {
			submitter.disabled = false;
			if (result.type === 'success') {
				onSuccess();
			}
			await update();
		};
	}}
>
	<!-- fields -->
	<button type="submit">Save</button>
</form>
```

### Key Points

- **`method="POST"` required** — `use:enhance` errors without it
- **`v.parse` for schema** (hard error), **`fail()` for constraints** (user-facing)
- `decode-formdata` runs **server-side** in the action
- Return prior field values in `fail()` data so the form repopulates
- `use:enhance` without callback: auto-resets form, invalidates data, handles redirects
- Custom `SubmitFunction` overrides default post-submission behavior — call `update()` to restore it

## Tier 2: `onsubmit` + TanStack Query (SPA Fallback)

### When to Use

- No `+page.server.js` available (SPA mode, `adapter-static`, etc.)
- Submitting to external APIs via TanStack mutation
- No SvelteKit form actions lifecycle

### Core Pattern

```svelte
<script lang="ts">
	import * as v from 'valibot';
	import { decode } from 'decode-formdata';

	import { assert } from '$lib/assert';

	const CreateItemSchema = v.object({
		name: v.pipe(v.string(), v.minLength(1)),
		amount: v.number(),
	});
</script>

<form
	onsubmit={event => {
		event.preventDefault();
		const { currentTarget, submitter } = event;
		assert(submitter instanceof HTMLButtonElement, 'submitter must be a button');
		submitter.disabled = true;
		const data = new FormData(currentTarget);
		mutation.mutate(
			{ data: v.parse(CreateItemSchema, decode(data, { numbers: ['amount'] })) },
			{
				onSuccess,
				onSettled: () => {
					submitter.disabled = false;
				},
			},
		);
	}}
>
	<input name="name" type="text" required />
	<input name="amount" type="number" required />
	<button type="submit">Create</button>
</form>
```

### Multiple Submit Buttons (Tier 2)

Use a `$state` variable so all buttons share the disabled state:

```svelte
<script lang="ts">
	let disabled = $state(false);
</script>

<form
	onsubmit={event => {
		event.preventDefault();
		disabled = true;
		// ... parse and mutate
		mutation.mutate(parsed, {
			onSettled: () => { disabled = false; },
		});
	}}
>
	<button type="submit" {disabled} formaction="/members/?/promote">Promote</button>
	<button type="submit" {disabled} formaction="/members/?/remove">Remove</button>
</form>
```

### SSR Unused Import Warning (Tier 2 Only)

Svelte SSR strips `onsubmit` handlers — they're DOM-only. If `decode` is only referenced inside an `onsubmit` inline handler, Rollup flags the import as unused in the SSR bundle.

**Fix**: extract a helper function in `<script>` that calls `decode()`:

```svelte
<script lang="ts">
	import { decode } from 'decode-formdata';

	function decodeFormData(formData: FormData) {
		return decode(formData, { numbers: ['amount'], dates: ['datedAt'] });
	}
</script>

<form onsubmit={({ currentTarget }) => {
	const parsed = v.parse(Schema, decodeFormData(new FormData(currentTarget)));
	// ...
}}>
```

This does not apply to Tier 1 — `decode` runs server-side in the action.

### Key Points

- **Always call `event.preventDefault()`** — Svelte 5 does NOT auto-prevent default on `onsubmit`
- **Use `mutate`, never `mutateAsync`** — let per-call `onSuccess`/`onError`/`onSettled` handle outcomes
- `submitter` is `HTMLElement | null` — assert it's an `HTMLButtonElement`
- **Handler is synchronous** — no `async`, no `try/finally`
- **`onSettled` re-enables the submitter** (runs on both success and error)
- **`onSuccess` handles post-success logic** (form reset, closing dialog/sheet, etc.)

## Shared Conventions

### Field Naming

- **camelCase** for all form field `name` attributes (e.g., `studentNumber`, `closesAt`)
- Schema property names must match field names exactly

### `decode()` Options

Specify non-string types explicitly:

```typescript
decode(data, {
	numbers: ['amount', 'quantity'],
	dates: ['datedAt', 'expiresAt'],
	arrays: ['tags', 'categories'],
});
```

### Common Valibot Schema Patterns

```typescript
// Required non-empty string
v.pipe(v.string(), v.minLength(1));

// Optional string (empty string becomes undefined)
v.optional(v.pipe(v.string(), v.minLength(1)));

// Email
v.pipe(v.string(), v.email());

// Array of non-empty strings
v.array(v.pipe(v.string(), v.minLength(1)));

// Number / Date
v.number();
v.date();
```

## Anti-Patterns

```svelte
<!-- BAD — onsubmit when use:enhance is available -->
<!-- If you have a +page.server.js, use form actions + use:enhance -->
<form onsubmit={handler}>

<!-- GOOD — use:enhance with form actions -->
<form method="POST" use:enhance={submitFn}>
```

```svelte
<script lang="ts">
	// BAD — $effect to handle mutation result (Tier 2)
	$effect(() => {
		if (mutation.isSuccess) onSuccess();
	});

	// GOOD — per-call onSuccess callback (Tier 2)
	mutation.mutate(data, { onSuccess });
</script>
```
